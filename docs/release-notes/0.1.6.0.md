Packages include Node.js; Rexarr runs on **http://localhost:3939**. See the
[install guide](https://moonlightlaboratory.github.io/rexarr/getting-started/install/).
The macOS app is not notarised: the first time, right-click `Rexarr.app` → *Open*.

## New

- **Disc ripping is on by default.** Rexarr watches your optical drives out of the box; a disc is still only ripped
  when you press *Rip*, unless *Rip automatically* is ticked. Existing installations keep their setting.

- **Disc audio tracks**: the Discs page now lists every audio track of a title and keeps only the best one per
  language by default (lossless > DTS > Dolby Digital, then channels and bitrate, never commentary). Tick any
  combination of tracks per title and *Apply to all titles* copies it to every episode on the disc; the rest are
  dropped by a stream copy.
- **Rip time and size**: a rip shows elapsed time and time left while it runs, and how long it took when it finishes.
  Before ripping, the Discs page estimates the size of the rip and of the encode that follows it.

- **Ripped files are imported reliably**: Rexarr now tells Sonarr the series and episode, and Radarr the movie, of
  each ripped file (Manual Import) instead of asking the app to scan the folder, which Sonarr skipped because
  "Show (Year) - Disc 1" is not a series name. Every file is checked afterwards, DVD rips are imported as DVD
  quality, and each file's result is written to the disc log.
- **Import finished rips automatically** (Settings → Disc ripping, on by default): every 10 minutes, films and
  episodes left in the rip folder – a failed import, files copied there by hand – are handed to Radarr and Sonarr;
  *Import rip folder now* does it at once and lists what happened to each file.
- **Check import access** (Settings → Disc ripping): asks Radarr and Sonarr whether they can see the rip folder,
  so a rip that cannot be imported is caught before the first disc.

- **Better disc matching**: a disc label is matched against your own library first – titles, alternate titles and
  AniDB's name for each season – so "SNAFU_2_DISC_1" becomes *My Teen Romantic Comedy SNAFU*, season 2 ("SNAFU Too!"),
  and a trailing number, "S2", "II" or "2nd Season" is read as a season. Search results are scored instead of taking
  the first hit. **Match again** re-runs this on a disc that was matched wrongly.

- **Specials and extras on discs**: each title can be an episode, a Sonarr special (season 0, when TVDB lists
  specials) or an extra – OP, ED, Extra, OVA, Special or a name of your own – which goes into an `Extras` folder next
  to the show. Titles numbered past the season's last episode are flagged. *Include extras and specials* (Settings →
  Disc ripping) also lists short titles such as creditless OP / ED.

- **Keep the computer awake while working** (Settings, on by default): while a disc is scanned or ripped, or a
  file encoded, Rexarr stops the computer from going to sleep – `caffeinate` on macOS, the Windows power API,
  `systemd-inhibit` on Linux – and lets it sleep again when nothing is running. System → Status shows when it is.

- **Discs for titles not in Sonarr / Radarr** are added when the rip starts (or with *Add to Sonarr now* on the
  Discs page, to pick episodes by name). They go into the root folder and quality profile your library uses for that
  kind of title – TV, anime, movies, anime movies – or the ones set in Settings, and are **not monitored** by
  default, so adding a show to import one disc never starts downloading the rest of it.

## Fixes

- **A delivery that imported nothing was reported as done.** Radarr and Sonarr report their import commands as
  "completed" even when they imported nothing – the rip folder is mapped to a path that does not exist, the files are
  not where the app looks, a file is rejected – and Rexarr took that as success: the rip was *done* with no error
  while the files sat in the rip folder. The rip now fails with what happened, both paths and where the files are,
  and the rip-folder import can still bring them in later.
- **Encodes at a time**: the limit (Settings → FFmpeg, now also on the Activity page) could be exceeded – a job only
  counted once ffmpeg started, so jobs still probing their file let others start. With the limit at 2, three encodes
  ran at once; now the third waits.
- **Discs on macOS**: macOS mounts a DVD as soon as it is inserted, and MakeMKV could then only use "OS access mode",
  which fails on most discs – scans finished in a second with "No titles found on this disc". Rexarr now unmounts the
  volume (the disc stays in the drive) before scanning and ripping, and says so if MakeMKV still cannot open a disc.
- **Adding a title from a disc** used the first root folder and quality profile: TV shows went into `/anime`,
  every movie into *Anime Movies*, all with "Any" – and shows were monitored, so Sonarr would start downloading
  every episode that was not on the disc.
- **Raw rips were imported**: raw MakeMKV files were written straight into the rip folder, so a rip that failed
  before encoding left uncompressed files there, which the rip-folder import picked up. Discs are now ripped and
  encoded in Rexarr's local cache, and only finished, compressed files are moved to the rip folder (copied under a
  temporary name and renamed when complete, so a half-copied file is never seen).
- **Disc labels of generic words**: a label such as "MOVIE_DISC" or "BONUS" matched a library title by those words
  alone – "MOVIE_DISC" became *No Game No Life: The Movie*. Only real title words count now.

**Upgrading**: nothing to do. Windows installs over the old version, macOS and Linux replace the folder; your
settings and data stay where they are.
