## Downloads

| Platform | File |
| --- | --- |
| Windows 10 / 11 | `win-x64-installer.exe` · portable `win-x64.zip` · 32-bit `win-x86-installer.exe` / `win-x86.zip` |
| macOS 11+ | Apple silicon `osx-arm64-app.zip` · Intel `osx-x64-app.zip` · terminal `osx-arm64.tar.gz` / `osx-x64.tar.gz` |
| Linux | `linux-x64.tar.gz` · `linux-arm64.tar.gz` · `linux-arm.tar.gz` · Alpine `linux-musl-x64.tar.gz` / `linux-musl-arm64.tar.gz` |
| FreeBSD | `freebsd-x64.tar.gz` (needs `pkg install node22`) |
| Docker | `docker pull ghcr.io/moonlightlaboratory/rexarr:0.1.7.0` · `docker pull moonlightlaboratory/rexarr:0.1.7.0` |

Packages include Node.js; Rexarr runs on **http://localhost:3939**. See the
[install guide](https://moonlightlaboratory.github.io/rexarr/getting-started/install/).
The macOS app is not notarised: the first time, right-click `Rexarr.app` → *Open*.

## New

- **System → Updates**: every release Rexarr has published, newest first, with its notes rendered in the UI —
  what is installed, what is newer, and what changed in between. The list is read from GitHub, cached for six
  hours, refreshed by the *Check for updates* task twice a day and by the *Check* button, and a new release is
  written to System → Events once. Rexarr still does not update itself: each newer release says how to install it
  for the way this instance was installed (package, Docker image, or source).

- **Documentation site**: the whole guide now lives at <https://moonlightlaboratory.github.io/rexarr/> — install
  and setup, every page of the UI, disc ripping end to end, a settings reference with the JSON key behind each
  field, the API, troubleshooting and development notes. It is built from `docs/` on every push, and the **?** in
  the header opens it (System → Status links it too).

- **NAS templates**: ready-made app files for **Unraid**, **ZimaOS / CasaOS**, **TrueNAS SCALE**, **Synology DSM**
  and **OpenMediaVault**, each with that system's paths, user ids and device passthrough, plus a
  [NAS and home servers](https://moonlightlaboratory.github.io/rexarr/getting-started/nas/) page covering hardware
  encoding, disc ripping and the mistakes that bite on a NAS. Rexarr also warns now when its own data folder is on
  an SMB / NFS share, where a dropped share can lose the settings file.

- **MakeMKV and Docker**, a page of its own: why the published image cannot rip (MakeMKV may not be
  redistributed, and its glibc binaries will not run on the Alpine image), how to build the Debian image that can,
  how to pair Rexarr with a MakeMKV container you already run — through a shared folder, either as virtual drives
  or as finished files for the rip-folder import — and how to keep the two from fighting over the drive. With a
  compose file for the MakeMKV build at `docker/docker-compose.makemkv.yml`.

- **Docker Hub**: the image is published to `moonlightlaboratory/rexarr` as well as GHCR — same build, same tags.
  The CasaOS / ZimaOS app store listing lives in `distribution/casaos` and is submitted from there.
