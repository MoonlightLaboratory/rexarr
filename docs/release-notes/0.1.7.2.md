## New

- **Notifications** (Settings → Connections): Rexarr can tell you when an encode or a disc finishes or fails, and
  when a new release is out — through Discord, Slack, Telegram, ntfy, Gotify, Pushbullet, an Apprise server (which
  covers IFTTT and the rest) or a plain webhook. Add as many targets as you like; each picks its own events, so
  the phone can get failures only while a channel gets everything. **Test** sends one message with the values on
  screen before you save. A target that fails is written to System → Events and never holds up the job it was
  reporting on. **Add notification** opens a picker laid out like Sonarr's, one card per kind with a link to that
  service's own instructions, and there is a **Custom Script** kind that runs a program of yours with the event in
  its environment (`REXARR_EVENT`, `REXARR_TITLE`, `REXARR_MESSAGE`, `REXARR_FAILED`, …).

- **Settings → Experiments**, and the first one in it: **barcode scanning**. Scan the barcode on a disc case with
  your phone — the page shows a QR code that opens Rexarr's scanning page on the phone — and Rexarr works out what
  the disc is, adds it to Radarr / Sonarr if it is not there yet, and keeps it on a list of discs it expects.
  Numbers are looked up at MusicBrainz and UPCitemdb, neither of which needs an account. Experiments are off by
  default, can change between releases, and each one says where to report it when it misbehaves. A camera needs
  HTTPS, so over plain http the page asks for the number instead.

- **A ripping to-do list**, the second experiment: the Discs page can show what Radarr and Sonarr would still
  like a better copy of — their cutoff-unmet lists — as **Insert disc for…**, with what is on disk now and which
  kind of disc would improve it. A 1080p remux is not improved by a Blu-ray, so those appear only when a UHD disc
  would help, and 2160p remuxes are left out. Discs whose barcode you scanned are marked and sorted first.

## Fixes

- **The interface got a pass over its spacing and controls.** Gaps between form fields came in four different
  sizes because a field's own margin was added to the gap of the grid it sat in; a grid now owns the spacing, a
  card's padding is even on all four sides, and a section heading has more air above it than below. Fields that
  shared a row no longer drift apart vertically – a stretched field was handing its spare height to its own rows,
  which is why "Drive poll interval" sat below "makemkvcon binary" with their labels level.

- **Disc ripping and Local media are broken into sections** instead of one long two-column wall, each with a
  heading: MakeMKV, where rips go, what happens when a disc is inserted, which titles to rip, adding to your
  library, testing – and scanning, folders, metadata. Nothing moved out of either card.

- **Buttons and selects**: the small button had 1px of vertical padding, so a Test button was 44x18 with the icon
  crammed against the label; it is 66x26 now, and the notification rows use the same icons as the rest of the app.
  Selects were still the operating system's control inside our box, with its own arrow and spacing – they are
  drawn like the inputs now, chevron included, and the compact ones keep room for it.

- **Focus and glow**: a focused field shows an amber border, matching the accent the rest of Rexarr uses, with no
  halo – except the search box, which keeps a tinted one. Ticking a checkbox no longer leaves a glow behind it,
  and there is no focus ring on buttons.

- **A scan that finds nothing now says why.** "No titles found on this disc (all shorter than the minimum
  length?)" was a guess. Rexarr reads the disc again with no minimum before answering, so it can tell you which it
  is: *found 14 titles but none reached the 600s minimum, the longest is 2 min* — or *found no titles at all*,
  which points at the MakeMKV key, a drive whose firmware cannot decrypt Blu-ray, or, in Docker, the drive's
  `/dev/sg` node not being passed through. Where MakeMKV said something itself — *"Scsi error - ILLEGAL
  REQUEST:READ OF SCRAMBLED SECTOR WITHOUT AUTHENTICATION"* — that is quoted instead of guessed at. The exact
  `makemkvcon` source and minimum are written to the disc log either way.

- **Small things**: the count beside a nav item is square and centred with tabular figures, so it does not jump
  between 9 and 10; the header search placeholder fades with its underline instead of blinking out halfway
  through; the rip-folder import is called "Import finished rips", since it has handled films as well as episodes
  since 0.1.7.0.
