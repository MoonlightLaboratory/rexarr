## New

### Letterbox bars come off

**Letterbox bars** in a profile's Video section: *Keep them*, *Remove automatically*, or a crop of your own as
`width:height:x:y`.

Automatic measures a few seconds in five places across the file — skipping the logos and the credits — and crops
only when four fifths of what it saw agrees. A film whose shape changes partway through, an IMAX sequence or an
open-matte insert, is left alone and the log says why, because cropping to one measurement cuts into the taller
scenes and nobody notices until that scene arrives. A handful of pixels is not letterboxing either.

The crop is applied before everything else, so a downscale measures the real picture rather than the black.

### Cleaner metadata inside the file

The title written into the file was built from Rexarr's own note about where it came from, so an episode carried
**"Naruto - S01E01 - disc rip"** — and Jellyfin can be told to prefer that over the name it matched. It is the
show and the episode now, and **Settings → Encoding → Title inside the file** can write nothing at all, which is
the safer answer when Plex or Jellyfin disagree with it. The "Encoded by Rexarr…" comment can be turned off too.

### Bazarr

**Settings → Connections → Bazarr.** A disc that has just been imported is handed straight over — look at the
disk again, because the file is new, then search for whatever subtitles are still missing — rather than waiting
for Bazarr's own schedule to notice it. Rexarr already knows whether it was a film or a series and its Radarr or
Sonarr id, which is what Bazarr indexes by too.

Bazarr is told, not asked: one that is down or misconfigured goes to the disc's log and System → Events, and the
rip carries on. A missing subtitle does not make a good rip a bad one.

### Keyboard shortcuts

<kbd>g</kbd> then a letter goes somewhere — `g d` for Discs, `g m` for Movies — and <kbd>?</kbd> lists them
without leaving the page. A chord rather than single keys on purpose: a bare <kbd>d</kbd> would fire on the
first letter of "Die Hard". Nothing fires while you are typing.

### A command line

`rexarr-cli` ships beside `rexarr` and `rexarr-agent`, and drives a running Rexarr from a script:

```bash
rexarr-cli rip --drive 1 --profile anime --wait
```

`status`, `drives`, `discs`, `detect`, `rip` and `swap`, pointed at any Rexarr with `--server` and `--key` (or
`REXARR_URL` and `REXARR_API_KEY`). A drive is the number `drives` prints, its device path, or the label of the
disc in it. A rip uses what has already been chosen for that disc unless `--profile`, `--no-transcode` or
`--no-deliver` says otherwise, and `--wait` stays until it is finished.

It holds no state and reads no configuration — it is the same HTTP API the web UI uses — so a box with no screen
needs nothing else installed. `--json` for output a program can read, and the exit code is 0 when the thing asked
for happened and 1 when it did not, including a `--wait` that ends in a failed rip.

See [the guide](https://moonlightlaboratory.github.io/rexarr/guide/cli/).

### Three more things to send a webhook about

Notifications fired when an encode or a rip finished, which is only ever news after the fact. Three events join
them, so something else can react while the disc is still in the drive:

- **`disc.inserted`** — a disc was found in a drive, before it has been read
- **`rip.started`** — MakeMKV has begun copying it
- **`import.done`** — the files reached Radarr or Sonarr

`import.done` is deliberately not the same as `rip.done`: a rip with delivery turned off finishes without
importing anything, so only a rip that actually went through delivery sends it.

They go to every target Rexarr already supports — Discord, Slack, Telegram, ntfy, Gotify, Pushbullet, Apprise, a
plain webhook or a script — and each target still picks its own events, so a Home Assistant flow can listen for a
disc going in without the phone buzzing for it.

## Fixes

- **A notification target could not be saved with a new event.** The list of events a target may subscribe to was
  written out twice in the settings schema and once more in the shared type, so an event the type knew about was
  rejected when the settings were saved. There is one list now, and the type comes from it.
- **Pinch and scroll on a trackpad do what they should in a smart profile.** Every wheel event zoomed the canvas
  by a fixed step. A mouse survives that; a trackpad does not — two fingers on a trackpad are a scroll, so trying
  to pan zoomed instead, and a pinch arrives as a burst of small events that each zoomed a whole step, which is
  why the canvas shot in and out. A pinch is the one wheel event that carries ctrlKey, so that zooms — by how far
  the pinch moved, rather than a step at a time — and everything else pans. A pinch no longer zooms the page
  behind the canvas either.
- **"Detect disc" no longer makes a second entry for a disc already being read.** It compared the drive a rip is
  in against the listed drive exactly, where the poll compares them as the same device under two names. The same
  drive is `/dev/rdisk5` to MakeMKV and `/dev/disk5` to Rexarr's own detection, so the check missed.
- **A disc put back after a failure is picked up again.** The rule is that a disc still in the tray is not ripped
  twice "until it is swapped", but nothing watched for the swap — it was a six-hour timer. Put the same disc back
  in after a failed read and it sat there ignored; leave a disc in overnight and it was read afresh as if new. A
  tray that empties is the swap now. The six hours stay only as a backstop for a swap nobody saw, such as one
  made while a rip held the drive list still.
- **A disc swapped into a waiting drive is read from the drive it is actually in.** The drive took its new device
  but kept the source it was opened by, and cycling a tray routinely changes the device — so the scan could open
  the one the disc had just left.
- **A box set that is finished with stops advertising discs.** In History a set still listed the discs it had
  never seen — six rows of "Disc 3, not inserted yet, incoming" under two discs ripped days ago, and "2 of 8
  discs" about a set nobody is feeding. A finished set says how many discs it has. Putting one of the missing
  discs in brings it back to Current, where the estimate means something again.
