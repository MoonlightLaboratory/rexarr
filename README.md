# RexDB

**An open database of what is actually on a disc.**

A Blu-ray or DVD does not say which episodes it holds. The disc label is a 32-character guess
(`SWORD_ART_ONLINE_2_P1`), the titles are numbered from zero in whatever order they were authored, and nothing
anywhere says that part 2 of a set starts at episode 8 rather than episode 6. Every ripper has to guess, and the
usual guess — *(disc − 1) × episodes-on-this-disc + 1* — is wrong the moment a set is 7 + 7 + 5 + 5 instead of
four equal discs.

Somebody has already worked it out for that disc, by hand, with the case in front of them. RexDB is where that
goes so nobody has to do it twice.

## What is in it

One file per disc, saying which title on the disc is which episode:

```json
{
  "schema": 1,
  "kind": "series",
  "series": { "title": "Sword Art Online", "year": 2012, "tvdbId": 259640 },
  "season": 2,
  "disc": 2,
  "release": { "name": "Sword Art Online II Part 2", "publisher": "Anime Limited", "region": "B" },
  "labels": ["Sword Art Online 2 Part 2"],
  "titles": [
    { "index": 0, "episode": 8 },
    { "index": 7, "special": 12, "note": "Episode 14.5, \"Debriefing\"" }
  ]
}
```

That is the whole idea. The rest of this file is how a disc is recognised, and how to add one.

## How a disc is matched

An entry can carry any of three, and more is better:

| | |
| --- | --- |
| `barcodes` | The number on the case. Exact, and the strongest match there is — but somebody has to scan it. |
| `labels` | The volume label the drive reports. Needs nothing from anyone, but varies between pressings and regions, so an entry may list several. |
| `fingerprint` | The number of titles and their durations in seconds. Available the moment a disc is scanned, needs no barcode, and is distinctive enough that two different discs almost never collide. |

A client should prefer a barcode match, then a fingerprint match, then a label match, and should treat a label
match as a suggestion to show rather than an answer to apply silently.

**Do not invent a fingerprint.** It is the field most likely to be matched against automatically, so a wrong one
is worse than a missing one. Leave it out unless you read it off the disc yourself.

## Using it

Entries are plain files, so a client can read them straight from GitHub with no API and no account:

```
https://raw.githubusercontent.com/MoonlightLaboratory/rexarr/RexDB/index.json
https://raw.githubusercontent.com/MoonlightLaboratory/rexarr/RexDB/discs/tv/sword-art-online-259640/s02d02.json
```

`index.json` is generated by `scripts/validate.mjs` and holds every entry's barcodes, labels and fingerprint with
the path to its file, so a client fetches one small file to find out whether a disc is known at all.

## Contributing

See [CONTRIBUTING.md](CONTRIBUTING.md). In short: copy an entry, change it to match the disc in your hand, open a
pull request. CI checks the shape; a human checks that the episodes are right.
